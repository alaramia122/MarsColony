# ADR-001: Архитектура MVP и голосовая интеграция

- Статус: принято для MVP
- Дата: 2026-11-15

## Контекст

Проект должен поддерживать локальную настольную сессию с общим экраном, браузерными клиентами, ИИ-ведущим и голосовым управлением. Разработка и проверки выполняются через GitHub; установка на домашний компьютер проводится после готовности CI.

## Решение

1. Backend реализуется как модульный монолит.
2. PostgreSQL хранит игровое состояние и журнал изменений.
3. Сервер является единственным источником истины.
4. Веб-клиенты, Алиса и ИИ-адаптер используют единый API команд.
5. ИИ возвращает типизированные предложения; сервер валидирует и применяет игровые изменения после согласования.
6. Голосовой интерфейс реализуется навыком Яндекс Алисы через HTTPS webhook.
7. Домашний сервер публикует только необходимый HTTPS endpoint через reverse proxy или защищённый туннель.
8. AI Gateway отделяет игровые модули от конкретных моделей и провайдеров.

## Последствия

- Игровые правила реализуются один раз и доступны из всех интерфейсов.
- Алиса управляет навигацией и запрашивает данные через intents, а не напрямую обращается к базе.
- Команды, меняющие состояние игры, проходят полномочия, валидацию и подтверждение.
- Платные API можно заменить другим провайдером или локальным/ручным режимом.
- Модульный монолит упрощает локальное развёртывание и тестирование.

## Ограничения и проверки

- Навык Алисы требует публично доступного HTTPS webhook и соблюдения требований платформы.
- Секреты и токены не хранятся в репозитории.
- До запуска на домашнем сервере проверяются аутентификация webhook, права доступа, журналирование и поведение при недоступности внешней интеграции.
