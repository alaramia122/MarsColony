# MarsColony — Техническое задание

**Версия:** 0.1 · **Статус:** базовая архитектура MVP

## 1. Назначение

Система обеспечивает цифровое сопровождение настольной многопользовательской игры MarsColony: общий экран, персональные интерфейсы, серверную игровую логику, экономические расчёты, проекты, ИИ-ведущего и голосовое управление через Яндекс Алису.

## 2. Цели MVP

MVP обеспечивает локальную игровую сессию до трёх часов. Домашний компьютер выполняет роль сервера; игроки подключаются браузерами через Wi-Fi. Система поддерживает:
- создание и загрузку игровой сессии;
- игроков, роли, направления и полномочия;
- игровые периоды и детерминированный расчёт состояния;
- ресурсы, население, инфраструктуру, производство и исследования;
- типовые действия и проектное согласование;
- свободные предложения с ИИ-разбором;
- общий экран, персональные кабинеты и карту;
- события и ИИ-ведущего под контролем человека;
- голосовые команды через навык Яндекс Алисы;
- журнал событий, сохранение и восстановление;
- автоматические тесты и сборку через GitHub Actions.

## 3. Архитектурные принципы

### 3.1 Модульный монолит
MVP реализуется единым серверным приложением с разделёнными предметными модулями. Выделение сервисов выполняется при подтверждённой необходимости.

### 3.2 Сервер — источник истины
Игровое состояние хранится на сервере. Клиенты отправляют команды и получают обновления. Сервер проверяет полномочия, валидирует параметры, рассчитывает последствия и фиксирует изменения транзакционно.

LLM не изменяет игровое состояние напрямую. ИИ возвращает типизированное предложение или команду, которая проходит серверную проверку и согласование.

### 3.3 Единый API
Веб-клиенты, общий экран, ИИ-адаптер и интеграция Алисы используют единый API команд и запросов. Голосовой интерфейс не содержит самостоятельных правил игры.

### 3.4 Провайдер-независимый ИИ
AI Gateway изолирует систему от моделей и поставщиков. Провайдеры подключаются адаптерами. Вызовы платных API учитывают отдельную стоимость и ключи; подписка ChatGPT Plus не является API-кредитом. Система предусматривает режим без платного API.

## 4. Технологический стек

- Backend: Python 3.12+, FastAPI, Pydantic.
- Хранилище: PostgreSQL.
- Frontend: TypeScript, React, Vite.
- Синхронизация: WebSocket; HTTP API для запросов и команд.
- Карта: веб-картографический компонент с игровыми слоями.
- Контейнеризация: Docker Compose.
- Тестирование: pytest, API- и интеграционные тесты, frontend unit/component tests.
- CI: GitHub Actions.
- Голос: навык Яндекс Алисы через HTTPS webhook.
- Публикация домашнего сервера: HTTPS reverse proxy или защищённый туннель.

## 5. Модули backend

1. **Game Session:** сессии, сценарии, периоды, сохранение и загрузка.
2. **Identity & Roles:** игроки, роли, направления, полномочия и доступ.
3. **World & Map:** зоны, координаты, слои и объекты.
4. **Resources & Inventory:** типы ресурсов, запасы, склады и перемещения.
5. **Economy Engine:** производство, потребление, энергия, труд, финансы и балансы.
6. **Infrastructure:** здания, оборудование, состояние, износ, ремонт и отказы.
7. **Population:** численность, потребности, здоровье, профессии и квалификация.
8. **Research:** научные программы, технологии, зрелость, испытания и результаты.
9. **Projects & Approval:** заявки, сметы, зависимости, согласование и исполнение.
10. **Events & Game Master:** события, сводки, сценарные триггеры и контроль ведущего.
11. **AI Gateway:** адаптеры моделей, структурированный вывод, лимиты и аудит.
12. **Voice Adapter:** webhook Алисы, intents и вызовы API.
13. **Audit & Event Log:** журнал команд, переходов состояния и согласований.

## 6. Клиентские приложения

**Общий экран** отображает карту, слои, состояние колонии, ключевые балансы, активные проекты, события и временную шкалу.

**Персональный кабинет** отображает полномочия игрока, направления ответственности, заявки, бюджет, показатели, доступные действия и согласования.

**Адаптивный веб-клиент** работает в браузерах устройств локальной сети и использует серверные API.

## 7. Интеграция с Яндекс Алисой

Интеграция реализуется как навык Алисы с HTTPS webhook. Endpoint принимает запрос, проверяет контекст сессии, преобразует фразу в intent и вызывает внутренний API. Ответ сервера преобразуется в ответ Алисы и при необходимости в команду отображения на общем экране.

Начальный набор intents:
- открыть раздел или экран;
- перейти к области карты;
- изменить масштаб и включить слой;
- показать показатель или график;
- получить сводку по направлению;
- задать вопрос ИИ-ведущему;
- подготовить проект или заявку;
- запросить подтверждение действия.

Для изменения игрового состояния сервер проверяет пользователя, полномочия, параметры и состояние сессии. Значимые действия требуют явного подтверждения. Endpoint публикуется по HTTPS; секреты webhook и ключи хранятся в окружении, а не в репозитории.

## 8. Свободные предложения и ИИ

Конвейер обработки:
1. Получение текста и контекста сессии.
2. Извлечение намерения, сущностей, параметров и неопределённостей.
3. Формирование типизированного предложения.
4. Проверка полномочий, технологий, ресурсов, труда, сроков и зависимостей.
5. Возврат сметы, ограничений, рисков и уточняющих вопросов.
6. Согласование ответственными игроками.
7. Исполнение движком и запись результата.

Генерация новой сущности создаёт отдельную запись реестра с ID, типом, версией, описанием, параметрами, asset, требованиями, происхождением, статусом и историей проверки. Существующие сущности не перезаписываются.

## 9. Основные сущности данных

GameSession, Scenario, GamePeriod, Player, Role, Responsibility, Permission, ResourceType, ResourceStock, InventoryTransaction, MapRegion, MapLayer, WorldObject, Facility, Equipment, AssetCondition, ProductionProcess, ProductionRun, PopulationGroup, Profession, Skill, Technology, ResearchProgram, Experiment, Project, ProjectApproval, Event, AIProposal, GeneratedEntity, GeneratedAsset, AuditEvent, StateSnapshot.

Основные сущности получают стабильные идентификаторы, временные метки и историю изменений.

## 10. Надёжность и безопасность

Критические изменения состояния выполняются транзакционно и журналируются. Доступ к игровым функциям определяется ролью и полномочиями. Административные и ведущие функции защищаются отдельными разрешениями.

Внешний голосовой endpoint работает по HTTPS. Секреты хранятся вне Git. Публикуются только необходимые endpoints; база данных и внутренние сервисы остаются в локальной сети Docker.

## 11. Репозиторий и CI

GitHub хранит исходный код, документацию, Issues, Pull Requests и историю изменений. GitHub Actions запускает линтеры, тесты, сборку frontend/backend и проверку Docker-конфигурации.

Рекомендуемая структура:

├── backend/app/
├── frontend/
│   ├── shared-screen/
│   └── player-client/
├── data/

├── infrastructure/
├── .github/workflows/
└── docker-compose.yml
~~~

## 12. Критерии приёмки MVP

1. Несколько браузерных клиентов подключаются к одной сессии в LAN.
2. Игровое состояние синхронизируется между клиентами.
3. Сервер рассчитывает базовые материальные, энергетические и финансовые балансы.
4. Игрок создаёт типовой проект и проходит согласование.
5. Свободный текст преобразуется в типизированное предложение и проходит валидацию.
6. ИИ-ведущий формирует сводку и предлагает событие на подтверждение человеку.
7. Общий экран отображает карту и показатели.
8. Алиса выполняет навигационные и информационные команды через HTTPS.
9. Сохранение и загрузка восстанавливают состояние сессии.
10. GitHub Actions выполняет тесты и сборку.
