# Этап 4 — AI Gateway и ИИ-ведущий

**Статус:** первый вертикальный срез реализован в рабочей ветке; требуется CI и дальнейшая проверка.  
**Ветка:** `feat/stage4-ai-gateway-game-master`

## 1. Цель этапа

Дать игроку возможность описать проект обычным языком, получить структурированное предложение с предварительной сметой, допущениями, рисками и вопросами, проверить его сервером и только затем создать обычный черновик проекта. ИИ-ведущий также должен формировать сводки и предложения событий; эти функции расширяются отдельными срезами.

## 2. Архитектурные границы

- AI Gateway изолирует игровые модули от протокола и поставщика модели.
- Провайдер получает ограниченный контекст сессии и возвращает JSON по Pydantic-контракту.
- LLM не имеет доступа к БД, SQLAlchemy-моделям, игровым командам, инструментам или секретам.
- Сервис проверяет полномочия игрока, домены, тип проекта, численные пределы, каталог ресурсов и типы эффектов.
- Предложение сохраняется со статусом `pending_review`; его создание не создаёт проект и не меняет игровое состояние.
- Отдельное действие пользователя преобразует предложение в обычный проект со статусом `draft`.
- Далее работают существующие механизмы submit, независимых согласований, исполнения, аудита и расчётов.
- Все значимые переходы записываются в append-only журнал событий.

## 3. Контракт предложения

Обязательные поля:
- название и описание;
- тип проекта и одно или несколько направлений ответственности;
- бюджет, длительность в игровых периодах, труд FTE и энергия за период;
- ресурсные требования;
- ожидаемые типизированные результаты, поддерживаемые проектным движком.

Поясняющие поля:
- обоснование;
- допущения;
- риски;
- вопросы, требующие уточнения.

Численные оценки модели являются предложениями. Серверные ограничения и сценарные параметры имеют приоритет. Сгенерированные данные не считаются инженерно подтверждёнными.

## 4. Провайдеры и конфигурация

Первый адаптер поддерживает API, совместимые с OpenAI Chat Completions. Настройки передаются через окружение:
- `MARS_AI_PROVIDER=openai_compatible`;
- `MARS_AI_BASE_URL`;
- `MARS_AI_API_KEY`;
- `MARS_AI_MODEL`;
- `MARS_AI_TIMEOUT_SECONDS` (необязательно, по умолчанию 45).

По умолчанию `MARS_AI_PROVIDER=disabled`: запрос возвращает HTTP 503 с объяснением, что провайдер не настроен. Ключи не сохраняются в БД и не попадают в Git. Подписка ChatGPT Plus не используется как API-кредит. Специфические адаптеры YandexGPT и других провайдеров подключаются отдельно после проверки актуальных API, авторизации и бесплатных лимитов.

## 5. API

- `POST /api/v1/sessions/{session_id}/ai/proposals` — преобразовать текст в предложение.
- `GET /api/v1/sessions/{session_id}/ai/proposals` — список предложений сессии.
- `POST /api/v1/sessions/{session_id}/ai/proposals/{proposal_id}/create-project` — явное создание проектного черновика.

Все endpoints требуют сессионный `X-Player-Token`. Полномочия повторно проверяются сервером. Повторное создание проекта из одного предложения блокируется.

## 6. Хранение

Таблица `ai_proposals` содержит сессию, автора, исходный текст, структурированный результат, статус, ссылку на созданный проект и временные метки. Секреты провайдера и полные HTTP-заголовки не сохраняются.

## 7. Безопасность и отказоустойчивость

- Входной текст рассматривается как недоверенные данные.
- Ответ модели валидируется схемой и доменными ограничениями.
- Ограничены размер входного текста, время ожидания и размер ответа провайдера.
- Сетевые ошибки и невалидный JSON преобразуются в контролируемую ошибку 503.
- При отключённом провайдере игровые API и обычный workflow проектов продолжают работать.
- Ни одно предложение не применяется автоматически.
- Создание проекта из предложения не означает его согласование или запуск.

## 8. Критерии приёмки среза

1. Валидный запрос создаёт сохраняемое предложение.
2. Невалидный ответ модели не создаёт запись и не меняет состояние игры.
3. Участник без полномочий не может запрашивать проектное предложение.
4. Предложение остаётся `pending_review` до отдельного действия игрока.
5. Явное действие создаёт стандартный черновик, который проходит обычные согласования.
6. Повторная обработка одного предложения отклоняется.
7. При отключённом AI Gateway возвращается контролируемая ошибка, а остальной API доступен.
8. Миграция и тесты проходят на SQLite unit-контуре и PostgreSQL CI.

## 9. Следующие срезы этапа 4

- Сводка ИИ-ведущего по текущему состоянию, отчётам периода и журналу событий.
- Предложение сценарных событий с обоснованием, вероятностью/условиями и подтверждением командира.
- Уточняющий диалог по неполным проектам без создания дубликатов.
- Реестр новых сущностей и история версий; инженерная проверка до использования в экономике.
- Настройки провайдеров через окружение/секреты и проверенные адаптеры для российских API.
- Интерфейс в React для диалога, просмотра сметы и явного создания черновика.
