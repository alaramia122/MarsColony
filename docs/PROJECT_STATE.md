## Назначение

MarsColony — многопользовательская настольная стратегическая НРИ о развитии марсианской колонии с цифровым сопровождением. MVP — локальная сессия до трёх часов, браузерные клиенты в домашней сети, общий экран и голосовой интерфейс через Яндекс Алису.

## Архитектура и принятые решения

- Backend: Python 3.12+, FastAPI, Pydantic; PostgreSQL.
- Frontend: React, TypeScript, Vite.
- WebSocket для уведомлений об изменениях; HTTP API для запросов и команд.
- Docker Compose и GitHub Actions.
- Модульный монолит; сервер — единственный источник игрового состояния.
- LLM формирует типизированные предложения и не меняет состояние напрямую.
- Экономика включает материальную, энергетическую, биологическую, демографическую, финансовую и технологическую подсистемы.
- Базовый сценарий Ares-1: 24 человека, четыре периода по 30 солов.
- Российские и международные инженерные источники рассматриваются совместно; игровые допущения отделяются от подтверждённых данных.

## Этап 3 — интегрирован, ожидает LAN-приёмки

Issue #9; PR #10; ветка `feat/stage3-web-clients-map`.

Реализованный срез:
- FastAPI WebSocket endpoint `/api/v1/sessions/{session_id}/stream`.
- Аутентификация первым WebSocket сообщением; токен не передаётся в URL.
- Начальный серверный snapshot, последовательность событий, доставка commit-событий из PostgreSQL и heartbeat.
- Клиентский reconnect с получением актуального snapshot.
- React/TypeScript/Vite приложение: создание и подключение к сессии, обзор, проекты, участники и карта.
- Общий экран через `?view=screen`; адаптивная компоновка для широкого экрана и мобильного браузера.
- Создание проектного черновика с несколькими направлениями, ресурсами на старте, FTE, энергией и ожидаемыми типизированными эффектами; отображение сметы и результатов, отправка на согласование, согласование/отклонение, запуск, подтверждение завершения и отмена.
- Командир назначает роли и зоны ответственности участникам через UI; ограничения назначения повторно проверяются backend.
- Карта поддерживает фильтры по реально присутствующим типам инфраструктурных объектов.
- История последних событий загружается из API и показывает серверные временные метки.
- WebSocket-индикатор различает подключение и переподключение; при отозванном/неверном токене автоматические попытки прекращаются и отображается ошибка.
- Сервер возвращает отдельный код закрытия для неизвестной сессии и недействительных учётных данных.
- Командир продвигает игровой период из обзора с передачей `expected_period`.
- Схематическая карта показывает объекты только с заданными координатами; остальные выводятся отдельно.
- Docker Compose web service на порту 8080; Nginx проксирует HTTP и WebSocket к API.
- Документация: `docs/STAGE3_DESIGN.md`, ADR-006.

WebSocket опрашивает PostgreSQL каждые 750 мс. Клиент воспринимает события как уведомления и перечитывает авторитетный HTTP snapshot. При reconnect сервер отправляет новый snapshot.

CI на текущем кодовом head: [Stage 0](https://github.com/alaramia122/MarsColony/actions/runs/43726165858), [Backend and web validation](https://github.com/alaramia122/MarsColony/actions/runs/43726154659) — success. Подтверждены 73 backend tests, frontend typecheck/build, PostgreSQL migrations, Compose config/build/start, доступность web/API, продвижение периода и восстановление состояния после перезапуска PostgreSQL/API.
