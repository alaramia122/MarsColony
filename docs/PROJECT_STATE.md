## Назначение

MarsColony — многопользовательская настольная стратегическая НРИ о развитии марсианской колонии с цифровым сопровождением. MVP — локальная сессия до трёх часов, браузерные клиенты в домашней сети, общий экран и голосовой интерфейс через Яндекс Алису.

## Принятые решения

- Backend: Python 3.12+, FastAPI, Pydantic.
- Frontend: React, TypeScript, Vite.
- PostgreSQL — постоянное хранилище; WebSocket — обновление клиентов.
- Docker Compose и GitHub Actions; на старте модульный монолит.
- Сервер — единственный источник игрового состояния; LLM формирует типизированные предложения, сервер проверяет и применяет подтверждённые команды.
- Алиса и веб-клиенты используют единый API; AI Gateway не привязан к одному провайдеру.
- Экономика включает материальную, энергетическую, биологическую, демографическую, финансовую и технологическую подсистемы.
- UI имеет оперативный, аналитический и инженерный уровни детализации.
- Базовый численный сценарий — Ares-1: 24 человека, четыре периода по 30 солов.
- При дальнейшей калибровке используются российские источники (Роскосмос, РКК «Энергия», ИМБП РАН, ЦПК, профильные институты РАН), NASA и другие открытые материалы. Для каждого параметра фиксируются происхождение, условия измерения, временная база и применимость.

## Этап 1 — в работе: игровое ядро и экономика

**Первый вертикальный срез:** [PR #5](https://github.com/alaramia122/MarsColony/pull/5), CI Stage 1 run #7 успешно прошёл: доменные и persistence-тесты, проверка JSON и применение Alembic migration к PostgreSQL 16. Реализованы доменный расчёт одного периода, API сессий, PostgreSQL-модели, Alembic migration и Docker Compose. Текущая реализация покрывает базовые балансы Ares-1; дальнейшая работа — интеграционные тесты с PostgreSQL, усиление инвариантов и детализация экономики.

Цель — создать серверное доменное ядро, которое воспроизводимо загружает сценарий, создаёт игровую сессию, хранит состояние ресурсов, рассчитывает игровой период и фиксирует историю изменений.

Порядок реализации:
1. Доменная модель: сценарий, сессия, игровой период, ресурсы, запасы, потоки и события.
2. Детерминированный расчётный движок и инварианты материальных/энергетических балансов.
3. PostgreSQL persistence, миграции и транзакционное изменение состояния.
4. HTTP API для создания сессии, чтения состояния и продвижения периода.
5. Интеграционные тесты полного цикла на Ares-1 и воспроизводимости.
6. Docker Compose для локального запуска backend и PostgreSQL.

Критерий готовности этапа 1: сервер создаёт сессию Ares-1, рассчитывает несколько периодов, сохраняет результаты и историю в PostgreSQL, восстанавливает состояние после перезапуска и проходит автоматические проверки.
