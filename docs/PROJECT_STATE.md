## Назначение

MarsColony — многопользовательская настольная стратегическая НРИ о развитии марсианской колонии с цифровым сопровождением. MVP — локальная сессия до трёх часов, браузерные клиенты в домашней сети, общий экран и голосовой интерфейс через Яндекс Алису.

## Принятые решения

- Backend: Python 3.12+, FastAPI, Pydantic.
- Хранилище: PostgreSQL; frontend: React, TypeScript, Vite.
- WebSocket для синхронизации клиентов; Docker Compose и GitHub Actions.
- На старте используется модульный монолит.
- Сервер — единственный источник игрового состояния. Клиенты отправляют команды; сервер проверяет и применяет их транзакционно.
- LLM формирует типизированные предложения и не меняет состояние напрямую.
- Алиса и веб-клиенты используют единый backend API.
- Экономика включает материальную, энергетическую, биологическую, демографическую, финансовую и технологическую подсистемы.
- Базовый сценарий — Ares-1: 24 человека, четыре периода по 30 солов.

## Этап 1 — реализация завершена, CI пройден

Полная реализация находится в PR #6. Изменения готовы к интеграции в main.

### Состав реализации

- Универсальный исполнитель материальных процессов с ограничением по сырью, энергии и вместимости склада.
- Рецептуры кислородной ISRU, тепличного выпуска и водной линии вынесены в версионируемый JSON сценария.
- Каталог ресурсов задаёт ID, ключ состояния, единицу измерения и вычислительную точность.
- Места хранения задают ресурс, физическую область и вместимость.
- Электрические нагрузки назначаются диспетчерским группам с приоритетами и минимальной устойчивой мощностью.
- Выделенная электрическая энергия ограничивает фактический выпуск энергозатратных процессов.
- Аккумулятор имеет начальный и минимальный заряд, ёмкость, пределы мощности заряда/разряда и КПД в обоих направлениях.
- Состояние заряда аккумулятора входит в сохраняемое состояние сессии и восстанавливается из PostgreSQL.
- Сценарий семантически проверяется до создания сессии.
- Сессия хранит неизменяемый JSON-снимок сценария.
- Продвижение периода защищено от устаревших и конкурентных команд через expected_period и блокировку строки.
- Состояние и событие периода фиксируются одной транзакцией; проверен откат при конфликте записи.
- OpenAPI-контракт, health/readiness endpoints и инструкция локального запуска.
- CI проверяет PostgreSQL 16, полный сценарий, конкурентные команды, OpenAPI, сборку Compose, запуск и восстановление после перезапуска PostgreSQL/API.
