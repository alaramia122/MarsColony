# Проверка реального AI provider

Unit-тесты `backend/tests/test_ai_gateway.py` проверяют форматы запросов, обработку ответов и fallback с подменными сетевыми ответами. Они не доказывают, что ключ, folder ID, квоты, модель и сетевой доступ пользователя настроены правильно.

Для реальной проверки предусмотрен одноразовый smoke test. Он делает один запрос к маршруту AI Gateway и проверяет, что провайдер вернул валидный JSON с `status: "ok"`.

## Перед запуском

1. Заполнить локальный `.env` одним из вариантов из `.env.example`.
2. Для Yandex AI Studio проверить API key, folder ID, права сервисного аккаунта и доступность выбранной модели.
3. Убедиться, что AI provider не отключён: `MARS_AI_PROVIDER=yandex_ai_studio` либо задан реестр `MARS_AI_PROVIDERS` и маршрутизация `MARS_AI_TASK_ROUTING`.
4. Не вставлять ключи в Git, issue, чат или командную строку; хранить их только в локальном `.env`.

## Запуск

Если `.env` был изменён после старта контейнеров, пересоздать только API-контейнер:

```powershell
docker compose up -d --force-recreate api
```

Затем выполнить один запрос:

```powershell
docker compose exec api python -m app.ai_smoke --task briefing
```

Доступные задачи: `briefing`, `project_proposal`, `project_clarification`, `scenario_event`, `knowledge_entity`. По умолчанию используется `briefing`.

Успешный результат содержит `AI_PROVIDER_SMOKE_OK`, задачу, время ответа и короткое сообщение модели. Ненулевой код возврата означает, что конфигурация, соединение или формат ответа не прошли проверку.

**Важно:** запрос тарифицируется выбранным AI-провайдером. Запускать один раз для проверки, а не в цикле. Smoke test подтверждает соединение и JSON-контракт, но не заменяет проверку полного игрового сценария через интерфейс.

## Полная проверка через UI

После успешного smoke test:
1. Открыть игровую сессию и войти командиром или участником с ролью, имеющей право создавать AI-предложения.
2. Открыть «ИИ-ведущий» и запросить оперативную сводку.
3. Попросить подготовить конкретный проект, проверить черновик, уточнить его и создать обычный проект.
4. Убедиться, что проект проходит стандартные полномочия и согласования и что ИИ не меняет состояние колонии сам.
5. Сохранить обезличенные сообщения об ошибках и результат проверки; API key и полный `.env` не отправлять.

Если smoke test успешен, а UI не работает, проверять уже API-маршрут, сессионный токен, полномочия игрока и состояние браузерного клиента.
