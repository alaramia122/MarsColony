# Реализация гексагональной карты — этап 1

**Связанная задача:** [Issue #19](https://github.com/alaramia122/MarsColony/issues/19)  
**Ветка:** `feat/hex-map-placement-issue-19`

## Что реализовано

- Серверная система координат axial `q,r` для pointy-top гексов.
- Преобразования axial ↔ Cartesian и округление дробных координат до ближайшего гекса.
- Расстояние между гексами, шесть соседей и нормализация footprint.
- Детерминированное отображение прежних координат `x/y` в процентах в axial-координаты. Старые данные не переписываются.
- Таблица `map_placements` для предложений площадки и утверждённых размещений.
- API чтения карты, предложения площадки и профильного решения.
- При создании предложения сервер проверяет полномочия, тип и состояние проекта, версию карты и занятость footprint.
- Для строительного проекта обязательны решения направления `construction` и всех направлений проекта.
- Автор предложения не может согласовать собственную площадку.
- Командирское распоряжение оформляется отдельно, требует обоснования и попадает в историю решений.
- При изменении версии карты перед финальным размещением геометрия проверяется повторно.
- После утверждения альтернативные предложения площадки того же проекта переводятся в состояние `superseded`.
- Строительный проект нельзя запустить без утверждённой площадки.
- Карта интерфейса загружает серверный реестр, отображает утверждённые размещения и позволяет подать предложение с координатами q/r.

## API

- `GET /api/v1/sessions/{session_id}/map`
- `POST /api/v1/sessions/{session_id}/map/placements`
- `POST /api/v1/sessions/{session_id}/map/placements/{placement_id}/decisions`

Все операции требуют заголовок `X-Player-Token`.

## Ограничения текущего этапа

Это первый вертикальный срез, а не завершение Issue #19.

- Выбор площадки в UI пока задаётся координатами q/r вручную; интерактивный выбор гекса мышью/клавиатурой и pan/zoom ещё предстоит сделать.
- Footprint поддерживается сервером, но визуальный редактор размера/формы объекта ещё не сделан.
- Текущие инфраструктурные объекты со старыми x/y отображаются через совместимое вычисляемое представление; автоматической записи их новых q/r в БД нет.
- Слои геологии, открытий, транспорта, экспедиций, маршрутов и зон пока не подключены к реальным игровым событиям.
- История перемещений транспорта/экспедиций и точность научных наблюдений — следующий этап.
- Browser E2E с двумя ролями ещё не добавлен.

## Проверки

Новые unit/integration тесты покрывают геометрию гексов, преобразование legacy-координат, запрет самосогласования, обязательные профильные решения, конфликт footprint и запрет запуска строительства без утверждённой площадки. Полный CI и ручной двухклиентский тест должны пройти до слияния.
