# Гексагональная карта — реализация Issue #19

**Ветка:** `feat/complete-hex-map-issue-19`  
**Миграции:** `0011_map_placements`, `0012_map_position_history`

## Реализованные возможности

### Координатная модель и интерфейс
- Сервер хранит axial-координаты `q/r`, не зависящие от размера окна и масштаба.
- Реализованы преобразования axial ↔ Cartesian, округление до ближайшего гекса, расстояние, соседи и нормализация footprint.
- В интерфейсе — интерактивная pointy-top сетка, выбор гекса мышью, подсветка выбранной/занятой/запретной площадки.
- Панорамирование перетаскиванием, масштабирование колёсиком и кнопками, сброс вида.
- Размер площадки выбирается в UI: 1, 7 или 19 гексов. Сервер повторно проверяет footprint и пересечения.
- Экранные координаты вычисляются из axial; масштабирование не изменяет игровые координаты.

### Пространственный реестр и слои
Хранятся инфраструктура и строительные предложения, месторождения, научные открытия, транспорт, экспедиции, маршруты/сети и зоны ограничений. Слои включаются независимо. Маршруты с геометрией `metadata.path` рисуются поверх сетки. Legacy-объекты с координатами `x/y` продолжают отображаться: сервер преобразует их в axial на чтении и сохраняет исходные метаданные и изображения.

### Размещение и ответственность
- Площадка предлагается из строительного проекта.
- Сервер требует решения строительства и профильных направлений проекта.
- Автор не может согласовать своё предложение.
- Командирское распоряжение — отдельное решение с обоснованием и записью в журнале событий.
- Занятость проверяется по всем ячейкам footprint; учитываются ожидающие согласования и утверждённые объекты.
- Запретные зоны блокируют размещение и перемещение.
- Перед подтверждением учитывается версия карты; устаревшие предложения перепроверяются.
- Проект, создающий инфраструктуру, нельзя запустить без утверждённой площадки.

### Исследования и операции
- Публикация месторождения/открытия требует завершённого проекта типа `research` или `exploration`, профильных полномочий, источника и оценки достоверности 0..1.
- Неопубликованные открытия отсутствуют в общем пространственном реестре.
- Транспорт и экспедиции создаются ответственными направлениями.
- Перемещать транспорт/экспедиции может руководитель транспорта или командир.
- Каждое перемещение добавляет неизменяемую запись истории с прежними/новыми координатами, автором, причиной и версией карты.
- Создание и перемещение публикуются через event log; WebSocket рассылает обновления подключённым клиентам.

## API
Все операции требуют `X-Player-Token`.

| Метод | Endpoint | Назначение |
|---|---|---|
| GET | `/api/v1/sessions/{id}/map` | Снимок пространственного реестра |
| POST | `/api/v1/sessions/{id}/map/placements` | Предложение строительной площадки |
| POST | `/api/v1/sessions/{id}/map/placements/{placement_id}/decisions` | Профильное решение |
| POST | `/api/v1/sessions/{id}/map/features` | Публикация открытия, месторождения, транспорта, экспедиции, маршрута или зоны |
| POST | `/api/v1/sessions/{id}/map/features/{feature_id}/position` | Перемещение транспорта/экспедиции |
| GET | `/api/v1/sessions/{id}/map/features/{feature_id}/history` | История перемещений |

## Автоматические проверки
Backend unit/integration tests покрывают геометрию, legacy-координаты, согласования, запрет самосогласования, конфликты footprint, блокировку запуска строительства, подтверждение источника открытия, полномочия транспорта, историю движения и запретные зоны.

Playwright browser acceptance test поднимает два независимых браузерных клиента, проверяет одинаковое отображение объекта, выбор гекса, WebSocket-обновление после перемещения и доступность карты обоим игрокам.

## Ограничения и допущения
- Область интерфейса сейчас ограничена радиусом 10 гексов вокруг центра; серверные координаты допускают расширение.
- Достоверность задаётся числом 0..1 и источником; физическая модель погрешности и объединение противоречивых измерений — отдельная механика.
- Маршрут задаётся ломаной из axial-точек; автоматическая маршрутизация с учётом рельефа и стоимости перемещения не входит в Issue #19.
- Открытия регистрируются после завершения исследовательского проекта; автоматическая генерация результатов симуляцией геологии — отдельный этап.
