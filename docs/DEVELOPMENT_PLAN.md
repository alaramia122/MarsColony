# MarsColony — план разработки

**Версия:** 0.9  
**Актуальность:** 2026-11-15

## 1. Цель

Создать цифровую платформу для локальной многопользовательской настольной сессии MarsColony продолжительностью до трёх часов. Домашний компьютер выполняет роль сервера; участники подключаются браузерами через Wi-Fi; общий экран показывает состояние колонии.

## 2. Принципы

- GitHub — единый источник кода, документации, задач и истории.
- Изменения выполняются вертикальными срезами в feature-ветках и проходят CI.
- Сервер — единственный источник игрового состояния; команды валидируются и фиксируются транзакционно.
- Игровая логика и расчёты детерминированы.
- ИИ подключается через провайдер-независимый адаптер и выдаёт типизированные предложения.
- Российские и международные инженерные источники рассматриваются совместно; применимость каждого источника оценивается отдельно.
- Pull Request объединяется только после отдельного разрешения владельца проекта.

## 3. Этапы

### Этап 0. Проектирование и подготовка — завершён

GDD, техническое задание, экономическая модель, матрица ролей, Ares-1, контрольный расчёт, тесты, CI и ADR. Плейтест перенесён до готовности локальной платформы (Issue #3).

### Этап 1. Игровое ядро и экономика — интегрирован

PR #6 объединён в `main`. Сценарные ресурсы и склады, материальные процессы, энергетическая диспетчеризация, аккумулятор, детерминированный расчёт, PostgreSQL persistence, журнал событий, FastAPI/OpenAPI, Docker Compose и интеграционные тесты.

### Этап 2. Участники, роли и проекты — интегрирован

PR #8 объединён в `main`, Issue #7 закрыта. Реализованы участники (до 20), сессионные токены, роли и 16 направлений, проектные карточки, согласования, резервирование бюджета, расход материалов, FTE, энергетическое исполнение и типизированные результаты строительства, производства, ремонта и исследований. CI на PostgreSQL 16 подтвердил 68 тестов и Compose recovery.

### Этап 3. Веб-клиенты и карта — интегрирован, ожидает LAN-приёмки

Issue #9; ветка `feat/stage3-web-clients-map`.

Реализовано:
- React/TypeScript/Vite веб-приложение с адаптивной компоновкой, общим экраном и персональными кабинетами.
- Обзор ресурсов, энергетики, инфраструктуры, проектов, участников и истории событий с серверными временными метками.
- Управление ролями и направлениями ответственности через интерфейс командира.
- Полная форма проектной сметы: бюджет, длительность, FTE, энергия, ресурсные требования и типизированные результаты.
- Карта с фильтрами по типам инфраструктурных объектов; используются только реальные координаты из данных.
- WebSocket snapshot, упорядоченные события, heartbeat, reconnect и восстановление через актуальный snapshot.
- Docker Compose, Nginx reverse proxy и CI для backend/frontend.

Автоматизированная приёмка: 73 backend-теста, TypeScript typecheck/build, PostgreSQL migrations, Compose build/start, API/web smoke и recovery — success ([CI run](https://github.com/alaramia122/MarsColony/actions/runs/43726154659)).

Осталась ручная приёмка на целевой домашней LAN: общий экран и не менее двух независимых устройств должны показывать одинаковый номер периода, ресурсы, проекты и события; необходимо проверить команды без перезагрузки страницы и восстановление после потери Wi-Fi. До этой проверки Issue #9 остаётся открытой.

### Этап 4. ИИ-ведущий и свободные действия — реализация в рабочей ветке, ожидает CI

Рабочая ветка `feat/stage4-ai-gateway-game-master`, PR #12.

Реализованы:
- AI Gateway с OpenAI-compatible и нативным Yandex AI Studio адаптерами; AI выключен по умолчанию, ключи передаются через окружение.
- Естественный язык → типизированное проектное предложение с валидацией полномочий, доменов, ресурсов, FTE и эффектов.
- Уточняющий диалог с сохранением истории версий проектного предложения.
- Оперативная сводка по актуальному snapshot колонии, проектам, участникам и последним событиям.
- Сценарные события с вариантами действий и последствиями; публикация/отклонение только командиром, журнал и WebSocket; без автоматического изменения ресурсов.
- Версионируемый реестр технологий, инфраструктуры, процессов, ресурсов и процедур; предложения проверяются командиром, предыдущая активная версия сохраняется как superseded.
- React-интерфейс ИИ-ведущего: сводка, генерация/уточнение проектов, проверка событий и реестр знаний.
- Миграции 0005–0008, API, тесты, .env.example, STAGE4_DESIGN и ADR-007/008.

Ограничения: реальный Yandex API требует пользовательских ключа и folder ID; mock-тесты проверяют протокол, но не заменяют интеграционный запрос. Утверждённые сущности остаются в реестре знаний и не меняют экономические расчёты автоматически. Ручная LAN-приёмка этапа 3 и плейтест остаются отдельными задачами.

### Этап 5. Яндекс Алиса

Intents, HTTPS webhook, адаптер Алисы, навигационные команды, запросы сводок, передача вопросов ведущему и подтверждение значимых действий. Критерий: навык выполняет согласованный набор команд в тестовой сессии.

### Этап 6. Интеграция, локальный запуск и плейтест

Полный сценарий, тесты API/экономики/multiplayer/сохранения, проверка восстановления, Docker Compose, инструкция LAN-развёртывания и CI. После готовности платформы проводится полноценный плейтест Ares-1; результаты фиксируются в Issue #3 и приводят к обновлению GDD, сценария, модели и тестов.

## 4. Приоритеты MVP

1. Игровое ядро и экономика.
2. Участники, роли, проекты и согласования.
3. Общий экран, персональные клиенты, синхронизация и карта.
4. ИИ-ведущий и свободные предложения.
5. Голосовая интеграция Алисы.
6. Генерация изображений и расширенные сущности.

## 5. Технологии и стоимость

Backend: Python/FastAPI, PostgreSQL. Frontend: React/TypeScript/Vite. Синхронизация: WebSocket и HTTP. Развёртывание: Docker Compose. AI Gateway отделяет приложение от поставщика моделей. Подписка ChatGPT Plus не включает API-кредиты; до подключения платного API оцениваются стоимость и лимиты.

## 6. Проверки качества

Unit-, API-, PostgreSQL integration-, сценарные и frontend tests; TypeScript typecheck/build; OpenAPI; Docker Compose build/start/recovery; проверки полномочий, транзакций, синхронизации и восстановления состояния.

## 7. Развёртывание

Сервер работает в локальной сети. Web UI публикуется на порту 8080, API — на 8000. PostgreSQL доступен контейнерам Compose. Для публикации внешнего HTTPS webhook Алисы будет добавлен reverse proxy или защищённый туннель. Секреты не хранятся в Git.
