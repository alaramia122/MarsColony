# MarsColony — План разработки

**Версия:** 0.1 · **Статус:** план MVP

## 1. Цель

Создать MVP цифрового сопровождения настольной игры для локальной сессии до трёх часов. Код, документация, задачи, тестирование и сборка ведутся через GitHub. Домашний компьютер настраивается после прохождения основных проверок в CI.

## 2. Принципы выполнения

- GitHub — единый источник кода, документации, Issues, Pull Requests и истории.
- Разработка ведётся небольшими вертикальными срезами, каждый из которых проверяется в CI.
- Игровая логика и экономические расчёты детерминированы.
- ИИ подключается через адаптер и выдаёт структурированные предложения.
- Сначала создаётся играбельный сценарий, затем добавляются расширенные возможности.
- Модульный монолит сохраняет предметные границы и ускоряет MVP.
- Архитектурные решения фиксируются в ADR.

## 3. Этапы разработки

### Этап 0. Проектирование и подготовка
Результаты: GDD, техническое задание, экономическая модель, матрица ролей, численно заданный стартовый сценарий Ares-1, переносимый контекст репозитория, контрольный расчёт, автоматические тесты, CI и ADR.

Критерии готовности:
- документы не противоречат друг другу и описывают единый MVP;
- стартовый сценарий содержит исходное состояние, запасы, мощности, население, производственные цепочки, потребление, бюджет, события и цели;
- численные параметры имеют единицы измерения, источник либо маркировку игрового допущения;
- расчёт стартового сценария воспроизводим и проходит базовые проверки материальных, энергетических и финансовых балансов;
- структура репозитория содержит инструкции для продолжения работы в новом чате/проекте, актуальное состояние, ADR и понятную навигацию;
- GitHub Actions запускается на Pull Request, проверяет JSON сценария, выполняет детерминированные тесты и формирует отчёт контрольного расчёта;
- открытые вопросы, риски и критерии перехода к этапу 1 зафиксированы;\n- базовый сценарий просмотрен владельцем проекта и проведён хотя бы один настольный плейтест либо явно принято решение перенести плейтест на начало этапа 1.

### Этап 1. Игровое ядро и экономика
Результаты: сессии, сценарии, ресурсы, запасы, население, инфраструктура, детерминированные материальные и энергетические балансы, игровой период, журнал и сохранение.

Критерий готовности: тест воспроизводит несколько периодов и проверяет балансы.

### Этап 2. Роли, проекты и согласование
Результаты: игроки, направления, полномочия, типовые действия, проектные карточки, бюджетирование, согласование, строительство, производство, ремонт и исследования.

Критерий готовности: несколько игроков подготавливают, согласуют и выполняют проект.

### Этап 3. Веб-клиенты и карта
Результаты: общий экран, персональный кабинет, карта, тематические слои, WebSocket-синхронизация и адаптивная работа в браузере.

Критерий готовности: общий экран и минимум два клиентских устройства отображают согласованное состояние.

### Этап 4. ИИ-ведущий и свободные действия
Результаты: AI Gateway, преобразование текста в типизированный проект, серверная валидация, сводки, предложения событий, реестр новых сущностей и история assets.

Критерий готовности: свободное предложение превращается в карточку, проходит проверку и ожидает утверждения человека.

### Этап 5. Алиса
Результаты: intents, HTTPS webhook, адаптер Алисы, навигационные команды, запросы сводок, передача вопросов ведущему и подтверждение значимых действий.

Критерий готовности: навык выполняет согласованный набор команд в тестовой сессии.

### Этап 6. Интеграция и выпуск
Результаты: полный сценарий, тесты API/экономики/multiplayer/сохранения, проверка восстановления, Docker Compose, инструкция развёртывания и CI-сборка.

Критерий готовности: тестовая партия проходит от начального состояния до итогового отчёта; сборка воспроизводится в GitHub Actions.

Подробные исходные значения и результаты контрольного прогона приведены в [SCENARIO_ARES_01.md](SCENARIO_ARES_01.md). Скрипт расчёта — проектный артефакт этапа 0; он не заменяет реализацию доменного движка на этапе 1.\n\n## 4. Приоритеты MVP

1. Игровой цикл, ресурсы и детерминированная экономика.
2. Роли, проекты, полномочия и согласование.
3. Общий экран, персональные клиенты и синхронизация.
4. Карта и объекты.
5. ИИ-разбор свободных предложений и ИИ-ведущий.
6. Голосовая интеграция Алисы.
7. Генерация изображений и расширенные сущности.

Голосовой интерфейс входит в MVP. Первая версия охватывает навигацию, запросы показателей и общение с ведущим. Управление критическими игровыми действиями вводится после проверки аутентификации, полномочий и подтверждения.

## 5. Недельный интенсивный прототип

Недельный план создаёт демонстрационный вертикальный срез, а не гарантирует готовность полного сбалансированного продукта.

| День | Результат |
|---|---|
| 1 | Документы, сценарий, роли, модель данных и ADR |
| 2 | Backend-каркас, сессия, ресурсы и расчёт периода |
| 3 | Производство, энергетика, население, проекты и тесты |
| 4 | Общий экран, кабинет игрока, карта и синхронизация |
| 5 | ИИ-предложения, валидация, сводки и события |
| 6 | Алиса: intents, HTTPS webhook и навигация |
| 7 | Интеграционные тесты, плейтестовый сценарий и сборка |

Каждый день завершается коммитом, тестами и обновлением Issues. При невыполнении критерия этап переносится; качество игрового ядра имеет приоритет над декоративными функциями.

## 6. GitHub workflow

- main содержит проверенную интегрированную версию.
- Работа ведётся в короткоживущих feature/docs branches.
- Изменения объединяются через Pull Request.
- CI запускает форматирование, линтинг, тесты и сборку.
- PR содержит цель, затронутые модули, проверки и миграции.
- Каждая функциональность имеет Issue с критериями приёмки.
- Решения фиксируются в docs/decisions/ADR-NNN.

## 7. ИИ-инструменты и стоимость

ChatGPT Plus используется для проектирования, анализа, ревью и подготовки задач. Бесплатные тарифы других моделей применяются для независимого ревью, когда доступны.

AI Gateway отделяет приложение от провайдера. Перед подключением платного API оцениваются лимиты, стоимость, задержка и качество структурированного вывода. Подписка ChatGPT Plus не включает автоматически API-кредиты OpenAI. Ключи задаются в окружении.

## 8. Проверки качества

Обязательны unit-тесты доменной логики и формул, интеграционные тесты API и БД, сценарные тесты игровых периодов, синхронизация клиентов, проверка полномочий, сохранение/восстановление, детерминизм и балансы, сборка контейнеров и frontend в CI.

## 9. Развёртывание

После успешного CI домашний компьютер подготавливается как локальный сервер: Docker Engine и Compose, LAN-доступ, резервное копирование PostgreSQL, HTTPS endpoint для Алисы и секреты вне репозитория. Клиентские устройства используют адрес сервера в домашней сети.

## 10. Риски и меры

| Риск | Мера |
|---|---|
| Чрезмерная детализация экономики | Вертикальный срез и агрегирование второстепенных процессов |
| Нестабильные ответы LLM | Типизированные схемы, валидация и подтверждение |
| Расходы на API | Провайдер-независимый gateway, лимиты и fallback |
| Доступ Алисы к домашнему серверу | HTTPS, проверка запросов, минимальная поверхность публикации |
| Перегрузка интерфейса | Агрегированные показатели и разделение общего/личного экрана |
| Партия выходит за 3 часа | Ограниченный сценарий, тайминг и плейтесты |
| Конфликты параллельной разработки | Контракты модулей, небольшие PR и единая интеграция |

## 11. Definition of Done

Задача завершена, когда реализация соответствует критериям приёмки, тесты проходят в GitHub Actions, документация обновлена, изменения доступны в PR, а игровой эффект проверен на тестовом сценарии.
